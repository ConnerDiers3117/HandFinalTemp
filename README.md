Sensor Addition:

I added a flex sensor to the hand, this way it can move in sync with real life stimuli, the flex sensor bends and sends a value to the Arduino, the Arduino then sends a FLEX amount to the server which then sends a message to the servos which move appropriately. I went for an intuitive approach where the hand only bends when the flex sensor bends downwards this updates within the server fairly fast and brings the hands down quickly there is very little delay. When the servo is not bent the hand stays at an up position so the flex amount and servo degree amount are inversely proportionate, I chose this design because I envisioned a future model that would fit inside a glove or other hand device with sensors for each finger this lets servos "grasp" an object, as it stands the hand cannot actually hold any weight within its grasp and must be oriented vertically to let gravity close the hand when the flex sensor is at a certain value. A future iteration would ideally have two sets of five servos that way the hand can be closed with the force of a servo instead of gravity. 

Improvements: 

As stated earlier I added onto the hand by adding the flex sensor, this is an improvement because it lets you physically interact with the hand and have it react to that input, moving the user interaction from a computer to a tangible object that closely mimics natural hand function, I believe this makes the hand much more intuitive to use and removes the need to use sliders or commands to move it, I kept the hand model and sliders in because I wanted to be able to debug issues and that way I can isolate what hardware isn't working properly. I also improved the model itself as it also updates with the hand position in real time, closely mimicking the servo hand. Another improvement I added to the code is the console log updates, I wanted to be able to see the exact angle the hand is working at to better fine tune certain fingers and so I can know if certain values are maxed out or being under valued. 

Design Process:

As I said earlier the design was meant to be intuitive by nature allowing users to not need any sort of prior knowledge or external information, this led to the project being rather minimal in design, with most of the hardware being the same, aside from the added sensor. I wanted the code to do the brute force of the work to keep the UI minimal and easy to understand. Another important design feature I wanted was live updates, I wanted the hand to move as quickly as possible to minimize delay and to add the humanness to it, the hand slightly fluctuates up and down since the flex sensor doesn't sit at an exact angle regardless of how still you hold it, I think this imperfectness adds to the experience because it feels like the micro movements in your hand directly translate to the servo hand and it replicates it, the only current downfall to this is that all the fingers move at the same time at the same set angle so each finger moves a little up and down despite there being one flex sensor. Ultimately it comes down to trying to keep the hand simple enough to be easy to use and complex enough to enable a human feel to the servo hand, this was important to me because I want my exact movements to translated to the servo even those very small shakes and flexes we naturally do, If the hand wasn't as reactive I feel as if it would lose that humanness that makes it familiar enough to anticipate what it will do when receiving input, when there is a disconnect between the user and the model it can feel like the interaction is dictated by a preset movement or overly dampened sensitivity it can make the user feel like the hand is leading the interaction not the user leading the interaction. I didn't want to fight the natural movements of our fingers and hands and instead wanted to implement that familiarity to the hand so users can use it more intuitively.
